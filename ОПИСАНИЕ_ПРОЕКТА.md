# Best-Face — описание проекта

Документ описывает, **что делает программа и как она это делает**: конвейер обработки, модели, формулы метрик,
правила отбора, форматы данных и настройки. Установка и запуск — в [README.md](README.md), лицензии моделей —
в [THIRD_PARTY_LICENSES.md](THIRD_PARTY_LICENSES.md). Значения параметров по умолчанию взяты из
[config.yaml](config.yaml) и кода и соответствуют текущей версии.

---

## 1. Назначение

Фотограф снимает каждого человека **несколькими кадрами**: кто-то моргнул, улыбнулся, отвернулся, хмурится,
смотрит в сторону. Программа берёт **папку со всеми кадрами вперемешку** и:

1. находит на каждом кадре лицо;
2. **группирует кадры по людям** (не зная заранее ни числа людей, ни границ серий);
3. внутри группы выбирает **один лучший кадр** — серьёзное лицо с открытыми глазами, смотрящее прямо в камеру,
   резкое, ровно стоящее, хорошо «узнаваемое» для систем распознавания лиц;
4. сохраняет лучшие кадры, отчёт и HTML-обзор для ручной проверки.

Программа работает офлайн, на CPU или GPU (CUDA, DirectML, CoreML), под Windows, macOS и Linux.

## 2. Конвейер

```
Папка с фото
   │
   ▼
[1] Сканирование: jpg/jpeg/png/webp/bmp, сортировка по имени (порядок = порядок съёмки)
   │   чтение файла + EXIF-время съёмки (в потоках, на несколько кадров вперёд)
   ▼
[2] Детекция лиц (YuNet) → bbox, 5 точек, confidence; выбор «главного» лица
   ▼
[3] Выравнивание по 5 точкам → кропы 112×112 и 224×224
   ▼
[4] Эмбеддинги: ArcFace 512-dim (группировка), FaceRes 1024-dim (узнаваемость, пол/возраст)
   │   MediaPipe FaceLandmarker: глаза, взгляд, мимика, поза головы
   │   NIMA: эстетика кропа лица
   ▼
[5] Кэш на диск (frame_cache.npz) — всё выше считается один раз
   ▼
[6] Кластеризация кадров по людям (ArcFace, EXIF-время)
   ▼
[7] Скоринг кадров в каждой группе: метрики Q1–Q11, жёсткие и относительные фильтры
   ▼
[8] Нумерация групп в порядке исходной папки, экспорт: best/, rejected/, report.json, contact_sheet.html
```

Этапы 1–5 — самые долгие, этапы 6–8 занимают секунды. Поэтому настройки группировки и скоринга можно менять
и пересчитывать результат почти мгновенно (из кэша).

## 3. Модели

| Роль | Модель | Файл | Вход / выход | Обязательна |
| --- | --- | --- | --- | --- |
| Детекция лиц + 5 точек | YuNet (OpenCV Zoo) | `face_detection_yunet_2023mar.onnx` | изображение (масштабируется до `max_det_size`=1280 по большей стороне), bbox + 5 точек + confidence | да |
| Группировка по людям | ArcFace MobileFaceNet (InsightFace, WebFace600K) | `w600k_mbf.onnx` | кроп 112×112, `(x−127.5)/127.5`, NCHW → 512-dim, L2-нормирован | да |
| Глаза, взгляд, мимика, поза | MediaPipe Face Landmarker | `face_landmarker.task` | кроп вокруг лица (bbox + 35%) → 478 ландмарков, 52 blendshapes, матрица поворота головы | нет (без неё: глаза оцениваются по пикселям, мимика и поза — по 5 точкам, взгляд не оценивается: Q10 = 0.5) |
| Узнаваемость, пол, возраст | Human FaceRes | `human_faceres.onnx` | кроп 224×224, RGB 0..255 (нормировка внутри графа; раскладка входа определяется по модели) → 1024-dim, пол, возраст | нет (без неё Q8 считается по ArcFace) |
| Эстетика лица | NIMA (MobileNet, AVA) | `nima_mobilenetv2.onnx` | кроп 224×224, ImageNet-нормировка → распределение оценок 1..10 | нет (без неё Q9 — оценка освещения по гистограмме) |

ArcFace отвечает **только за группировку**; качество кадра он не оценивает. Все модели, кроме `w600k_mbf.onnx`,
лежат в репозитории; она скачивается при первом запуске и разрешена только для некоммерческого использования.

**Выбор провайдера ONNX Runtime:** CUDA → DirectML → CoreML → CPU; принудительно — переменной
`BEST_FACE_PROVIDER=cpu|cuda|dml|coreml`. Должен быть установлен **один** пакет `onnxruntime*`.

## 4. Детекция и выравнивание

- **Детектор:** порог confidence `0.5`, NMS IoU `0.4`, минимальный размер лица `min_face_px = 50` (меньшая сторона bbox).
- **Несколько лиц в кадре** (`detection.multi_face_policy`): `largest` — самое крупное (по умолчанию); `central` —
  ближайшее к центру среди лиц не мельче 25% от самого крупного; `best_conf` — с наибольшим confidence.
- **Кадры без лица** попадают в `rejected/` и в отчёт (`reason: no_face`), в группировке не участвуют.
- **Выравнивание:** преобразование подобия (поворот, масштаб, сдвиг) по 5 точкам к эталонному шаблону ArcFace
  для 112×112; тот же шаблон, масштабированный, — для 224×224.
- **Чтение файлов** идёт через буфер (`imdecode`), чтобы работали пути с кириллицей на Windows.

## 5. Группировка кадров по людям

Входные данные — ArcFace-эмбеддинги (L2-нормированные), так что сходство кадров = их скалярное произведение (cosine).

### 5.1. Матрица расстояний

```
sim   = E · Eᵀ                          # cosine между всеми парами кадров
adj   = sim + bonus·near − penalty·far  # поправка по времени съёмки
dist  = 1 − adj
```

- `near` — кадры, снятые рядом: по EXIF разница ≤ `time_window_sec` (8 с), а если EXIF-времени нет —
  разница номеров файлов ≤ `time_window_frames` (8). Бонус `bonus = threshold − threshold_time_hint` (0.50 − 0.40 = 0.10)
  помогает склеить «плохой» кадр серии (например, отвёрнутый), эмбеддинг которого «уплыл».
- `far` — кадры, снятые дальше `time_far_sec` (120 с); штраф `time_far_penalty`. В режиме «один человек — один кадр»
  штраф выключен (`0.0`): человека, снятого в разное время, нужно оставить в одном кластере.

### 5.2. Кластеризация

**Agglomerative, average-linkage (UPGMA)**, разрез по расстоянию `1 − threshold` (`threshold = 0.50`):
кластеры объединяются, если **среднее** сходство между ними не ниже порога. Раньше использовались связные
компоненты (single-linkage), но одна «мостовая» пара похожих лиц склеивала двух разных людей — отказались.

### 5.3. Контроль связности

Если средний cosine внутри кластера ниже `min_cohesion` (0.60), кластер рекурсивно дробится с порогом, повышенным
на `split_step` (0.03) до `max_split_rounds` (6) раз. Если связность достичь не удалось, кластер помечается
`low_cohesion` (возможна склейка разных людей). Размер кластера критерием не является: длинная серия одного человека — норма.

### 5.4. Режимы

| `clustering.mode` | Что получается |
| --- | --- |
| `person` (по умолчанию) | один кластер на человека во всей папке; лучший кадр выбирается **один на человека**, даже если его снимали несколько раз |
| `series` | сначала папка режется на серии по паузам в съёмке больше `series_gap_sec` (14 с) между соседними кадрами, затем внутри серии разделяются люди; лучший кадр — **на каждую серию съёмки** |

Кадры без EXIF-времени серию не разрывают.

### 5.5. Большие папки

При числе кадров больше `dense_limit` (6000) режим `person` работает в два этапа, чтобы не строить матрицу n×n:
кластеризация внутри временных сегментов (или кусков по порядку файлов, если EXIF нет), затем слияние кластеров
по центроидам тем же average-linkage.

### 5.6. Центроид кластера

Центроиды (ArcFace и FaceRes) — **устойчивые**: среднее эмбеддингов, затем до 3 итераций отбрасывания кадров
с низким cosine к центру (порог: среднее − 1.5·σ, но не менее 0.03; остаётся не менее половины кадров),
чтобы отвёрнутые и смазанные кадры не «утягивали» центр.

### 5.7. Нумерация

После скоринга группы нумеруются **в порядке исходной папки** — по номеру файла лучшего кадра, поэтому
`person0001`, `person0002`, … в `best/` идут в порядке съёмки.

## 6. Метрики качества кадра

Все метрики нормированы в `[0, 1]`, больше — лучше. Q1–Q7, Q9–Q11 вычисляются по каждому кадру на этапе обработки
и кэшируются (сырые значения), Q8 и нормировки — при скоринге внутри группы.

| # | Метрика | Что измеряет | Как считается |
| --- | --- | --- | --- |
| Q1 | Резкость | фокус, смаз | дисперсия лапласиана по выровненному кропу 224×224 после гауссова сглаживания 3×3 (шум ISO не принимается за резкость). Нормировка по группе: `min(1, v / (0.8 · P90))`, где P90 — 90-й перцентиль группы, поэтому кадры с резкостью ≥ 80% от эталона считаются равными |
| Q2 | Фронтальность | поворот по 5 точкам | `min(d_правый_глаз–нос, d_левый_глаз–нос) / max(...)`; 1 — анфас, 0 — профиль |
| Q3 | Открытость глаз | моргание, полузакрытые глаза, прищур | `0.4·EAR/0.30 + 0.3·(1 − blink/0.6) + 0.3·(1 − (squint − 0.15)/0.5)`, каждая часть в [0, 1]; EAR по 6 точкам каждого глаза, `blink` и `squint` — blendshapes `eyeBlink*`, `eyeSquint*`. Без MediaPipe — оценка по пикселям (тёмный зрачок, контраст). Нормировка по человеку, см. п. 7.3 |
| Q4 | Нейтральность выражения | улыбка, открытый рот, брови | `1 − (expr − 0.05)`, где `expr` — взвешенная сумма blendshapes: улыбка ×1.0, `jawOpen` ×1.0, `mouthPucker` ×1.0, `browDown` ×2.0, `mouthFunnel` ×0.7, `mouthStretch` ×0.7, `browInnerUp`/`browOuterUp` ×0.4, `mouthDimple` ×0.5, `cheekSquint` ×0.5, `mouthFrown` ×0.5, `mouthUpperUp` ×0.3. Серьёзное лицо → expr около 0. Без MediaPipe — геометрия рта по 5 точкам |
| Q5 | Размер лица | детальность | доля площади bbox в кадре, затем нормировка по группе `min(1, v / (0.9 · max))` |
| Q6 | Экспозиция | пересвет, недосвет, контраст | `0.6·(1 − штраф за клиппинг) + 0.4·контраст` по выровненному кропу |
| Q7 | Confidence детектора | уверенность детекции | значение YuNet |
| Q8 | Узнаваемость | репрезентативность кадра | `(cos(FaceRes кадра, устойчивый центроид группы) + 1) / 2`; без FaceRes — по ArcFace |
| Q9 | Эстетика лица | освещение, равномерность, композиция кропа | NIMA: `(средняя оценка − 1) / 9`; нормировка по группе `max(0, 1 − (max − v)/0.25)`. Без NIMA — оценка освещения по гистограмме и зонам 3×3 |
| Q10 | Взгляд в камеру | куда смотрят глаза | отклонение взгляда от камеры: смещение зрачка (ландмарки радужки 468–477) за вычетом компенсации поворота головы `−0.0103·yaw` (коэффициент подобран регрессией на реальных съёмках), blendshapes `eyeLookIn/Out`, а по вертикали — смещение относительно типичного для этого человека. `Q10 = 1 − (отклонение − 0.3)/0.7`, малый шум не штрафуется |
| Q11 | Поза головы | прямо ли голова | гладкий штраф `exp(−½·((yaw/8)² + (pitch/10)² + (roll/6)²))` по углам из матрицы поворота MediaPipe; без MediaPipe — по Q2 |

## 7. Выбор лучшего кадра в группе

### 7.1. Итоговый score

Взвешенная сумма (веса из `scoring.weights`, сумма = 1; приоритет — серьёзное лицо, смотрящее в камеру):

| Метрика | Вес | | Метрика | Вес |
| --- | --- | --- | --- | --- |
| Q4 нейтральность | 0.17 | | Q1 резкость | 0.12 |
| Q3 глаза | 0.15 | | Q10 взгляд | 0.12 |
| Q8 узнаваемость | 0.10 | | Q11 поза | 0.10 |
| Q2 фронтальность | 0.08 | | Q9 эстетика | 0.06 |
| Q5 размер | 0.04 | | Q6 экспозиция | 0.04 |
| Q7 confidence | 0.02 | | | |

Сортировка: сначала кадры, прошедшие все фильтры, затем по убыванию score. Лучший кадр — первый.

### 7.2. Жёсткие фильтры (абсолютные)

| Причина в отчёте | Условие | Параметр |
| --- | --- | --- |
| `yaw_too_large` | поворот головы влево/вправо > 25° | `max_yaw_deg` |
| `pitch_too_large` | наклон вверх/вниз > 20° (нужен MediaPipe) | `max_pitch_deg` |
| `head_tilted` | наклон к плечу > 15° (нужен MediaPipe) | `max_roll_deg` |
| `mouth_open` | `jawOpen` > 0.10 | `max_jaw_open` |
| `not_frontal` | Q2 < 0.45 | `min_frontal_ratio` |
| `eyes_closed` | Q3 < 0.58 | `min_ear` |
| `blurry` | резкость < 15% от лучшей в группе | `min_sharpness_rel` |
| `low_confidence` | confidence детектора < 0.5 | — |

Фильтр `eyes_closed` **не срабатывает**, если глаза «закрыты» у всех кадров группы примерно одинаково (разница с лучшим
кадром ≤ 0.12): это особенность человека или съёмки (очки с бликами, узкий разрез), а не моргание.

### 7.3. Относительные фильтры (сравнение с лучшими кадрами этого же человека)

Абсолютные пороги плохо подходят разным людям, поэтому кадр выбывает, если он **заметно хуже лучших кадров своей группы**,
и при этом в группе есть из чего выбрать (если все остальные уже забракованы, кадр остаётся в игре):

| Причина | Сравнивается | Порог |
| --- | --- | --- |
| `eyes_half_closed` | Q3 кадра с 90-м перцентилем Q3 группы | `max_eye_gap` = 0.08 |
| `gaze_off` | Q10 кадра с 90-м перцентилем Q10 группы | `max_gaze_gap` = 0.25 |
| `not_neutral` | «сырой» `expr` кадра с 10-м перцентилем `expr` группы (самое нейтральное лицо) | `max_expr_gap` = 0.12 |

Нормировка Q3 по человеку: если у человека в норме Q3 ниже 0.75 (узкий разрез глаз), его открытые глаза
масштабируются к уровню 0.90, чтобы они не считались «моргнувшими». Если в группе все кадры с улыбкой,
выбирается наименее улыбающийся.

### 7.4. Особые случаи

- **Один кадр на человека:** выбирать не из чего, кадр отдаётся как есть, в отчёте `single_frame: true`.
- **Все кадры забракованы:** лучшим по score всё равно становится первый, серия помечается `low_quality_flag`.
- **«Почти равные кадры»** (`close_call`): два лучших score отличаются меньше `close_call_margin` (0.02), а прошедших кадров не
  больше `close_call_max_pool` (6) — выбор неуверенный, стоит посмотреть.
- **Ручной выбор** (п. 8.3) имеет высший приоритет и снимает флаги сомнения.

## 8. Входные и выходные данные

| `best/` | по одному лучшему фото на человека: `personNNNN_<исходное_имя>`; прежние `personNNNN_*` при повторном запуске переносятся в `best_prev/<время>/` (3 последние копии), чтобы не потерять ручное переименование |

```jsonc
                   "yaw_deg", "pitch_deg", "roll_deg", "frontal_ratio", "det_conf", "gender", "age" }]
  }],
  "rejected": [{ "file": "IMG_0001.jpg", "reason": "no_face" }]

```

В `metrics` лежат и нормированные значения Q1–Q11, и сырые сигналы (`*_raw`), по которым видно, какой именно
сигнал сработал на конкретном кадре.

### 8.3. Контактный лист и ручной выбор

В `contact_sheet.html` кадры сгруппированы по людям; лучший выделен, брак затемнён, указана причина. Есть фильтр
«только сомнительные» (низкое качество, подозрение на склейку, почти равные кадры). Клик по превью выбирает кадр вручную
(выбор запоминается в браузере), кнопка «Скачать manual_choices.json» сохраняет его вместе с путями к папке с фото и
результатам. Этот файл **перетаскивается на `run.bat`** (или передаётся как `best_face.py manual_choices.json`):
программа сама находит папки, применяет выбор по имени файла и пересобирает результат. По тем же выборам
`tune_weights.py` обучает веса скоринга (логистическая регрессия на парах «выбранный — остальные»).

Быстрая замена одного кадра: файл `personNNNN_*` из `best/`, перетащенный на `run.bat`, заменяется следующим по рейтингу
кадром того же человека (рейтинг — из `report.json`; номер кадра в имени ищется и в переименованных файлах). Конвейер
перезапускается по кэшу с ручным выбором (прежние ручные выборы из отчёта сохраняются), нумерация персон принудительно
остаётся прежней (`keep_person_ids`: группы должны совпасть с отчётом, иначе замена отменяется), а в `best/` заменяется
только один файл (`swap_best_photo`: прежний уходит в `best_prev/`).

### 8.4. Кэш

Ключ записи — путь, время изменения и размер файла. Весь кэш сбрасывается при смене моделей (по имени, размеру и mtime),
параметров детекции, политики выбора лица, версии формата или **исходного кода** этапов, влияющих на значения
(`detect`, `align`, `embed`, `ear`, `metrics`, `exif`). Формат — `.npz` без pickle (кэш лежит рядом с чужими фото, а загрузка
pickle из недоверенной папки позволила бы выполнить произвольный код). Ошибки чтения файлов не кэшируются. Отключается `--no-cache`.

## 10. Краевые случаи и ограничения

- **Близнецы и очень похожие люди** могут склеиться: помогает `min_cohesion` (флаг `low_cohesion`) и более высокий `threshold`.
- **Очки с бликами, узкий разрез глаз:** абсолютные оценки глаз у таких людей занижены; для этого введены сравнение с
  лучшими кадрами того же человека и исключение для «одинаково закрытых» кадров.
- **Нет MediaPipe-модели:** глаза оцениваются по пикселям, мимика и поза — по 5 точкам, взгляд не оценивается (Q10 нейтральна);
  фильтры `max_pitch_deg`, `max_roll_deg`, `max_jaw_open` и относительные фильтры по взгляду и мимике не применяются.
- **Коммерческое использование:** ArcFace `w600k_mbf.onnx` разрешена только для некоммерческих исследований; для
  коммерческого применения её нужно заменить (и заново подобрать `threshold`/`min_cohesion`), а условия датасетов,
  на которых обучены NIMA и FaceRes, проверить самостоятельно.
- **Ориентация снимков:** при декодировании OpenCV применяет EXIF-ориентацию, поэтому снимки, сохранённые «на боку»
  (например, ориентация 6), обрабатываются в правильном положении (проверено на реальных папках).
- **Пороги подобраны на съёмке детей в студийных условиях** (одинаковый фон и свет) и могут потребовать правки на других данных:
  `max_gaze_gap`, `max_expr_gap`, `max_eye_gap`.
- **Автоматической метрики качества группировки нет:** нужна размеченная выборка. Проверка проводилась вручную
  просмотром результатов на реальных папках.

## 12. Возможные улучшения

- Разметка эталонной выборки и автоматические метрики качества группировки и выбора.
- Замена ArcFace на модель с коммерческой лицензией; сравнение с другими эмбеддерами (например, dlib ResNet).
- Мягкие штрафы вместо жёстких фильтров; готовая модель качества лица (FIQA).
- Альтернативные алгоритмы кластеризации (HDBSCAN, Chinese Whispers), объединение нескольких эмбеддингов.
- Детектор SCRFD/RetinaFace для мелких и повёрнутых лиц; поддержка RAW.
