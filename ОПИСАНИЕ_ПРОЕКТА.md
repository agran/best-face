# Проект «Best-Face» — автоматический отбор лучшего фото из серии

> Это исходное проектное описание (ТЗ). Текущая реализация местами отличается:
> детектор — YuNet вместо SCRFD, кластеризация — average-linkage с поправкой по
> EXIF-времени. Актуальная инструкция по запуску — в [README.md](README.md).

## 1. Постановка задачи

Фотограф снимает каждого человека **серией** из нескольких кадров. В серии бывают
неудачные кадры: человек моргнул, отвернулся, смазался, гримаса, закрыты глаза,
не в фокусе и т.п.

Нужна программа, которая:

1. Берёт **папку со всеми фотографиями** (вперемешку, много людей, у каждого —
   несколько кадров).
2. Автоматически **группирует кадры в серии одного и того же человека**.
3. Внутри каждой серии **выбирает один лучший — самый «узнаваемый» — кадр** для
   системы распознавания лиц.
4. Сохраняет выбранные кадры (и, при желании, отчёт по каждой серии).

«Узнаваемый» здесь означает: кадр, который даёт **наиболее качественный и
стабильный эмбеддинг лица** для целевой системы распознавания, то есть на котором
человека легче всего корректно опознать.

> ⚠️ На этом этапе **реализация не требуется** — это техническое задание для
> другой нейросети/разработчика. Документ описывает _что_ и _как_ делать, какие
> модели использовать и какие метрики считать.

## 2. Целевая система распознавания (для совместимости)

Программа отбора должна давать результат, оптимальный именно для существующего
проекта Face-ID Kiosk. Поэтому крайне
желательно использовать **те же модели**, что и в продакшене. Ниже — что там
используется.

### 2.1. Активный продакшн-пайплайн Face-ID Kiosk

| Этап                          | Модель                            | Детали                                                                                                                                                         |
| ----------------------------- | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Детекция лиц**              | **SCRFD_500M**                    | ONNX, даёт bbox + **5 ключевых точек** (глаза, нос, углы рта) + confidence. Порог confidence `0.5`, NMS IoU `0.4`.                                             |
| **Выравнивание**              | affine 5-point (ArcFace template) | По 5 точкам строится аффинное преобразование к опорному шаблону ArcFace.                                                                                       |
| **Распознавание (эмбеддинг)** | **Human FaceRes**                 | Вход `224×224` RGB `[0..255]`, выход **1024-dim**, L2-нормализован. Файл `model-onnx/human_faceres_webnn.onnx` (WebNN) / `human_faceres.onnx` (WASM-fallback). |
| **Сравнение**                 | cosine similarity                 | Порог матча **0.40**; индекс ускоряется adaptive K-means.                                                                                                      |

Происхождение моделей (из `model_origins.md`):

- **Human FaceRes / FaceRes-Deep** — downstream-конвертация `av-savchenko/HSE_FaceRec_tf` (TFJS → ONNX), 1024-dim.
- **SCRFD_500M** — InsightFace SCRFD.
- **face-api FaceRecognitionNet** (fallback, 128-dim) — линия dlib ResNet-34.

### 2.2. Дополнительная (опциональная) модель распознавания

В репозитории есть скрипт `gen_descriptors_512.py`, который использует
**InsightFace `w600k_mbf.onnx`** (MobileFaceNet / ArcFace / WebFace600K):

- Вход `112×112`, нормализация `(x - 127.5) / 127.5` → `[-1, 1]`, layout `NCHW`.
- Выход **512-dim**, L2-нормализован.
- Эта модель сильнее как «универсальный» ArcFace-эмбеддер и удобна для
  кластеризации/проверки идентичности.

### 2.3. Рекомендация по моделям для Best-Face

| Назначение                      | Рекомендуемая модель                                | Почему                                                                                |
| ------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Детекция + 5 точек              | **SCRFD_500M** (`model-onnx/scrfd_500m.onnx`)       | Та же, что в продакшене; даёт точки для alignment и оценки позы.                      |
| Кластеризация серий             | **InsightFace `w600k_mbf.onnx`** (512-dim, ArcFace) | Более дискриминативный ArcFace-эмбеддинг → надёжнее группирует кадры одного человека. |
| Финальная оценка «узнаваемости» | **Human FaceRes** (1024-dim)                        | Чтобы метрика совпадала с целевой системой Kiosk.                                     |

Можно использовать одну модель для обеих задач (проще), но **двухмодельная схема
точнее**: ArcFace для группировки, FaceRes для финальной оценки под целевую систему.

> Файлы моделей кладутся в папку `models/` (пути задаются в `config.yaml`). Запуск —
> через `onnxruntime` (Python, `CPUExecutionProvider` достаточно для офлайн-батча).

## 3. Общий конвейер программы

```
Папка с фото
   │
   ▼
[1] Сканирование файлов (jpg/png/...)
   │
   ▼
[2] Детекция лиц (SCRFD_500M) → bbox, 5 точек, confidence
   │   (фильтр: ровно 1 «главное» лицо в кадре или выбор наибольшего)
   ▼
[3] Alignment по 5 точкам → кроп 112×112 (ArcFace) и 224×224 (FaceRes)
   │
   ▼
[4] Эмбеддинги:
   │   - ArcFace 512-dim (w600k_mbf) — для группировки
   │   - FaceRes 1024-dim (опц.) — для целевой метрики
   ▼
[5] Метрики качества каждого кадра (см. раздел 5)
   │
   ▼
[6] Группировка кадров в серии одного человека (см. раздел 4)
   │
   ▼
[7] Скоринг и выбор лучшего кадра в каждой серии (см. раздел 6)
   │
   ▼
[8] Экспорт: лучшие фото + отчёт (JSON/CSV)
```

## 4. Группировка кадров в серии (кластеризация по личности)

Цель — собрать все кадры одного человека вместе, **не зная заранее** ни числа
людей, ни границ серий.

### 4.1. Основной метод — кластеризация по эмбеддингам

1. Для каждого валидного лица получить **ArcFace 512-dim** эмбеддинг (L2-норм.).
2. Считать **cosine similarity** между всеми кадрами.
3. Объединять в одну личность, если `cosine ≥ THRESHOLD_GROUP`.
   - Рекомендуемый старт: `THRESHOLD_GROUP = 0.45..0.55` (подобрать на реальных
     данных; ArcFace WebFace600K обычно даёт «один человек» при cosine > ~0.4–0.5).
4. Алгоритм: **agglomerative / connected-components** по графу схожести
   (рёбра, где cosine ≥ порога) либо DBSCAN с метрикой `1 - cosine`.

### 4.2. Подсказка по порядку файлов (опционально, усиливает точность)

Серии обычно идут **подряд** по имени файла / времени съёмки (EXIF `DateTimeOriginal`).
Можно использовать это как дополнительный сигнал:

- Кадры, идущие подряд во времени **и** похожие по эмбеддингу → почти наверняка одна серия.
- Это помогает разделить двух **похожих** людей и склеить серию, где один кадр
  сильно искажён (отвёрнут) и его эмбеддинг «уплыл».

### 4.3. Обработка краёв

- Кадры без лица / с мусором → отдельная папка «rejected», не участвуют в сериях.
- Кадры с несколькими лицами → берётся самое крупное/центральное лицо (главный
  объект серии). Параметр поведения должен быть настраиваемым.

## 5. Метрики качества кадра

Для каждого кадра считаются нормированные в `[0, 1]` метрики. Это основа выбора
«лучшего» фото.

| #   | Метрика                              | Что измеряет                   | Как считать (ориентир)                                                                                                                                                                      |
| --- | ------------------------------------ | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q1  | **Резкость / фокус**                 | смаз, расфокус                 | Variance of Laplacian по области лица (čем выше — тем резче). Нормировать относительно серии.                                                                                               |
| Q2  | **Фронтальность (поза)**             | человек отвернулся?            | Из 5 точек SCRFD: симметрия глаз относительно носа. В Kiosk есть `_MIN_FRONTAL_RATIO = 0.45` (отношение ближний/дальний глаз к носу: 0 = профиль, 1 = анфас). Также оценить yaw/pitch/roll. |
| Q3  | **Открытость глаз**                  | моргнул?                       | Eye Aspect Ratio (EAR) или классификатор «open/closed». Закрытые глаза → штраф.                                                                                                             |
| Q4  | **Нейтральность/качество выражения** | гримаса, открытый рот          | Geometry рта/бровей; крайние выражения штрафуются (для распознавания нейтраль лучше).                                                                                                       |
| Q5  | **Размер лица**                      | мелкое лицо = мало деталей     | Доля площади лица в кадре / межзрачковое расстояние в пикселях. `_MIN_FACE_SIZE` в Kiosk = 50 px.                                                                                           |
| Q6  | **Экспозиция/освещение**             | пере-/недосвет, контраст       | Гистограмма яркости области лица; штраф за клиппинг в тенях/светах.                                                                                                                         |
| Q7  | **Детектор confidence**              | насколько уверенно это лицо    | Прямо из SCRFD (`≥ 0.5`).                                                                                                                                                                   |
| Q8  | **«Узнаваемость» эмбеддинга**        | насколько кадр репрезентативен | Косинусная близость эмбеддинга кадра к **медоиду/центроиду серии** (см. 6.2). Чем ближе к центру кластера — тем «эталоннее» и стабильнее распознаётся.                                      |

> Q1–Q7 — это «фотографическое качество» одного кадра. **Q8** — ключевая метрика
> «узнаваемости» относительно остальных кадров серии и относительно целевой
> модели распознавания.

## 6. Выбор лучшего кадра в серии

### 6.1. Жёсткие фильтры (hard gates)

Сначала отсеять заведомо непригодные кадры (если в серии остаётся ≥1 кадр после фильтра):

- confidence детектора < `0.5`;
- глаза закрыты (EAR ниже порога);
- |yaw| больше допустимого (сильный профиль), напр. > `30–40°`;
- размер лица < минимального;
- резкость значительно ниже лучших кадров серии (явный смаз).

Если после фильтров не осталось кадров — отдать лучший по score (раздел 6.3) и
пометить серию флагом «низкое качество» для ручной проверки.

### 6.2. Расчёт центра серии (для Q8)

1. Усреднить L2-нормированные эмбеддинги серии → центроид; снова L2-нормировать.
2. Q8 кадра = cosine(эмбеддинг кадра, центроид).
3. Альтернатива/дополнение — **медоид**: кадр с максимальной суммой cosine ко всем
   остальным (устойчивее к выбросам, чем центроид).
4. **Важно:** перед расчётом центра рекомендуется исключить явные выбросы
   (отвёрнутые/смазанные кадры), чтобы центр не «уехал» к плохим кадрам.
   Итеративно: посчитать центр → отбросить кадры с самым низким Q8 → пересчитать.

### 6.3. Итоговый скоринг

Линейная взвешенная сумма нормированных метрик (веса — стартовые, настраиваемые):

```
Score = w1·Q1(резкость)
      + w2·Q2(фронтальность)
      + w3·Q3(глаза открыты)
      + w4·Q4(нейтральность)
      + w5·Q5(размер лица)
      + w6·Q6(освещение)
      + w7·Q7(confidence)
      + w8·Q8(узнаваемость/центральность)
```

Рекомендуемые стартовые веса (сумма = 1.0), приоритет — узнаваемость и поза:

| Метрика                                    | Вес  |
| ------------------------------------------ | ---- |
| Q8 узнаваемость (центральность эмбеддинга) | 0.25 |
| Q2 фронтальность                           | 0.20 |
| Q1 резкость                                | 0.20 |
| Q3 глаза открыты                           | 0.12 |
| Q5 размер лица                             | 0.08 |
| Q6 освещение                               | 0.07 |
| Q4 нейтральность                           | 0.05 |
| Q7 confidence                              | 0.03 |

Лучший кадр серии = `argmax(Score)`.

> Все метрики Q1, Q5, Q6 нормировать **внутри серии** (min-max), т.к. абсолютные
> значения зависят от сцены. Q2, Q3, Q7, Q8 нормируются абсолютно (по физическому
> смыслу).

## 7. Вход / Выход

### 7.1. Вход

- Путь к папке с фото (рекурсивно или нет — параметр).
- Поддержка `.jpg .jpeg .png .webp .bmp` (+ при наличии RAW — заранее
  конвертировать в JPEG).
- Конфиг с порогами и весами (YAML/JSON).

### 7.2. Выход

- Папка `best/` — по одному лучшему фото на каждого человека (исходный файл,
  скопированный или со ссылкой), имя: `{person_id}_{исходное_имя}`.
- Папка `rejected/` — кадры без лица/брак (для контроля).
- `report.json` / `report.csv`:

```jsonc
{
  "persons": [
    {
      "person_id": 1,
      "best_photo": "IMG_2043.jpg",
      "score": 0.87,
      "frames": [
        {
          "file": "IMG_2041.jpg",
          "score": 0.61,
          "metrics": {
            "Q1": 0.5,
            "Q2": 0.9,
            "Q3": 1.0,
            "Q8": 0.93,
            "confidence": 0.99,
          },
          "selected": false,
          "rejected_reason": null,
        },
        {
          "file": "IMG_2042.jpg",
          "score": 0.42,
          "selected": false,
          "rejected_reason": "eyes_closed",
        },
        { "file": "IMG_2043.jpg", "score": 0.87, "selected": true },
      ],
    },
  ],
  "params": {
    "threshold_group": 0.5,
    "weights": {
      /* ... */
    },
  },
}
```

- Опционально — контактный лист (превью серии с подсветкой выбранного) для
  быстрой ручной проверки.

## 8. Технологический стек (рекомендация)

- **Язык:** Python 3.10+.
- **Инференс:** `onnxruntime` (CPU достаточно для офлайн-батча).
- **Обработка изображений:** `opencv-python`, `Pillow`, `numpy`.
- **Кластеризация:** `scikit-learn` (Agglomerative/DBSCAN) или собственный
  connected-components по матрице косинусов.
- **EXIF:** `Pillow` / `exifread` (для времени съёмки).
- Модели (кладутся в `models/`):
  - `scrfd_500m.onnx` — детектор;
  - `w600k_mbf.onnx` — ArcFace 512-dim (группировка);
  - `human_faceres.onnx` — FaceRes 1024-dim (целевая метрика).

### 8.1. Важные детали препроцессинга (чтобы совпасть с моделями)

- **SCRFD:** вход RGB; учесть, что в продакшене есть «baked resize»-варианты, но
  для офлайн-батча проще взять обычный `scrfd_500m.onnx` и ресайзить самим.
  Confidence ≥ 0.5, NMS IoU 0.4. (В Kiosk был баг сдвига bbox — центр якоря
  `ax * stride`, а не `(ax+0.5)*stride`; см. `scrfd-bbox-shift-bug.md` — учесть
  при своей реализации декодинга SCRFD.)
- **w600k_mbf (ArcFace):** alignment по 5 точкам → `112×112`, нормализация
  `(x - 127.5) / 127.5`, layout `NCHW`, выход 512-dim, **L2-normalize**.
- **Human FaceRes:** alignment по 5 точкам → `224×224`, RGB **`[0..255]` без
  нормализации** (модель делит на 255 и вычитает среднее внутри графа), выход
  1024-dim, **L2-normalize**.

## 10. Краевые случаи и риски

- **Близнецы / очень похожие люди** → могут склеиться в одну серию. Смягчается
  time-hint (раздел 4.2) и более высоким `threshold_group`.
- **Один кадр на человека** → нечего выбирать, отдать его как есть.
- **Все кадры серии плохие** → отдать лучший + флаг «требует проверки».
- **Очки/маски/головные уборы** → могут снижать качество эмбеддинга; не
  фильтровать жёстко, но учитывать в Q8.
- **Несколько людей в кадре** → политика `multi_face_policy`.
- **Сетевые пути Windows** (`\\server\share\...`) → возможны падения
  Python на длинных путях; копировать модели локально в `models/` перед запуском.

---

## 11. Критерий приёмки

1. Программа на тестовой папке корректно разбивает кадры по людям (ошибки
   группировки < N%, измерить на размеченном наборе).
2. В каждой серии выбранный кадр — фронтальный, резкий, с открытыми глазами и
   максимальной центральностью эмбеддинга (Q8).
3. Выбранные кадры дают **более высокий и стабильный** результат в целевой системе
   Face-ID Kiosk, чем случайный кадр серии (проверить на cosine к эталонам).
4. Есть отчёт с метриками по каждому кадру для ручной верификации.

### Приложение A. Сводка моделей репозитория Face-ID

- Детекторы: `scrfd_500m*.onnx` (актив), `retinaface_mbn025.onnx`,
  `blazeface.onnx`, `face_detection_yunet_2023mar.onnx`, `det_500m.onnx`.
- Рекогнайзеры: `human_faceres*.onnx` (актив, 1024-dim),
  `w600k_mbf*.onnx` (ArcFace 512-dim), `arcfaceresnet100-11-int8.onnx`,
  `insightface_r50_webface600k.onnx`, `sface_2021dec.onnx`,
  `edgeface_*.onnx` (архив), `faceapi_face_recognition.onnx` (128-dim, dlib-линия).
- Активные пороги Kiosk: cosine match **0.40**, SCRFD conf **0.5**, NMS IoU **0.4**.
